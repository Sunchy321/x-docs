\pnum
\term{函数}声明将函数、方法或闭包引入当前作用域。函数声明由关键字\tcode{func}标记，后跟函数名、参数列表、异常修饰符、返回类型和函数体。

\pnum
在同一个作用域中可以定义两个名称相同的函数，但是这些函数必须具有不同名称的命名参数（忽略顺序）。
如果两个函数在省略某些具有默认值的命名参数之后，剩余的命名参数名称完全相同（忽略顺序），则这也是一个编译错误。

\pnum
\tcode{return}以转移方式把返回值移交给调用方：函数体构造结果值并把它移动到调用方的结果位置（RVO 式），不进行复制。

\pnum
函数的返回类型可以省略，此时函数的返回类型为函数体的类型与函数中\tcode{return}语句参数类型的公共类型。
如果函数包含\tcode{throw}修饰符（\tcode{throw()}除外），则返回类型变为\tcode{$R$ !! $E$}，其中$E$为修饰符推导或指定的错误类型。不携带\tcode{throw}修饰符的函数默认不会抛出异常，其返回类型不受影响。参见~\ref{except.func.throw}。

\pnum
函数体为单个块或者\tcode{=>}后跟任意表达式和分号。如果采用后一种形式，则不能显式指定返回类型。

\pnum
实现中的函数可以为\term{方法}。参见~\ref{method}。

\pnum
函数中可以有另一个函数声明。此时如果内部函数使用了外部函数作用域中的值，该函数为\term{闭包}，否则为普通函数。

\pnum
\term{参数}为调用函数时传入其内的值。
如果函数不接受任何参数，则必须使用\tcode{()}标识而不能省略括号。
函数参数默认是不可变的，除非由\tcode{mut}修饰。

\pnum
参数可以为\tcode{this}参数、顺序参数或具名参数，且必须按照此顺序排列，并且\tcode{this}参数不能出现超过一次。
顺序参数和具名参数必须显式指定其类型，不能省略类型。
具名参数可以指定默认值。如果函数调用时没有提供对应的值，则视为传入该默认值。

\pnum
函数参数可以是一个模式，但视为处于绑定模式中，其中所有的标识符都视为一个绑定。这个模式不能是可失败的。

\enterexample
\begin{codeblock}

func foo((a, b): (int, bool)) {
    // \tcode{a} is \tcode{int}, \tcode{b} is \tcode{bool}
}

\end{codeblock}
\exitexample

\rSec1[param.qual]{参数修饰符}
\indextext{参数修饰符}

\pnum
参数修饰符修饰函数参数，指定参数的某些属性。

\rSec2[param.qual.mut]{\tcode{mut}}
\indextext{参数修饰符!\idxcode{mut}}

\pnum
\tcode{mut}修饰的参数是可变的，可以在函数内部被修改或重新赋值。\enternote 按值参数总是以移动方式传递：调用把实参位置的值转移给形参，实参随后失效。除非使用\tcode{ref}修饰或显式\tcode{clone}，调用处实参不会保留原值。\exitnote

\rSec2[param.qual.ref]{\tcode{ref}}
\indextext{参数修饰符!\idxcode{ref}}

\pnum
\tcode{ref}修饰的参数以引用方式传递，是位置引用（\ref{type.ref}）。除非使用\tcode{mut}修饰，否则参数是只读的。

\pnum
类型为$T$的\tcode{ref}参数实际上是类型为\tcode{$T$\&}（或\tcode{$T$ mut\&}）的引用参数的语法糖。
在函数内部使用该参数时，将会自动对参数进行解引用。
\tcode{ref}参数的子类型关系按其脱糖结果\tcode{$T$\&}的规则确定。
生命期可携带于\tcode{ref}参数的引用类型上，由函数声明处的生命期参数（\ref{generic}）绑定，未标注处由编译器推断。调用处被引用的实参位置在活引用期间不得被移出（借用检查）。

\pnum
\tcode{ref}参数将会按如下方式脱糖：

\begin{codeblock}
func foo(ref a: int) {
    a = 1;
}

let mut a = 0;

foo(ref a);
\end{codeblock}
变为
\begin{codeblock}
func foo(\{$r_a$}: int mut&) {
    *\{$r_a$} = 1;
}

let mut a = 0;

foo(&mut a);
\end{codeblock}

\rSec2[param.qual.lazy]{\tcode{lazy}}
\indextext{参数修饰符!\idxcode{lazy}}

\pnum
\tcode{lazy}修饰的参数是惰性求值的，只有在函数内部使用时才会计算实参的值。
\tcode{lazy}不能与\tcode{mut}修饰符一起使用。

\pnum
类型为$T$的\tcode{lazy}参数实际上是类型为\tcode{() once -> $T$}的闭包参数的语法糖。
\tcode{lazy}参数的子类型关系按其脱糖结果\tcode{() once -> $T$}的规则确定。
在函数内部首次读取该参数时，将会调用该闭包并将结果缓存，之后再次读取时直接使用缓存的值。

\pnum
\tcode{lazy}参数将会按如下方式脱糖：

\begin{codeblock}
func foo(lazy a: int) {
    bar(a);
}

let a = 0;

foo(a);
\end{codeblock}
变为
\begin{codeblock}
func foo(\{$c_a$}: () once -> int) {
    let \{$s_a$}: int? = nil;
    let \{$g_a$} = do {
        if let some \{$v_a$} = \{$s_a$} {
            \{$v_a$}
        } else {
            let \{$v_a$} = \{$c_a$}();
            \{$s_a$} = some \{$v_a$};
            \{$v_a$}
        }
    };

    bar(\{$g_a$}());
}

let a = 0;

foo(do { a });
\end{codeblock}

\rSec1[func.async]{异步函数}

\pnum
使用\tcode{async}修饰的函数称为异步函数。异步函数的调用立即开始执行函数体，直至第一个挂起点或函数体结束；调用的结果是\tcode{Future}（\ref{core.future}），函数体剩余的部分由当前任务域在其挂起期间交错推进。异步函数的启动是急切的：执行始于调用本身，与是否被\tcode{await}无关。

\pnum
\term{任务域}内的多个异步执行按确定性顺序交错，同一时刻至多一个在执行。域内交错是求值顺序语义的延伸：借用的有效性跨越挂起点保持不变，对挂起点之间的求值适用与普通表达式相同的借用检查规则（\ref{type.ref}）。\enternote 挂起不改变任何位置的可达性——其他任务无法持有本任务局部的引用（\ref{func.task}），域内交错又服从确定性顺序，因此跨挂起点持有引用是安全的。 \exitnote

\rSec1[func.task]{任务与并行}
\indextext{函数!任务}

\pnum
\term{任务}是并行的执行单元。任务经任务创建原语（如核心库的\tcode{spawn}）进入并行执行；本节定义任务边界的语义规则，创建原语的具体语法形态由核心库与运行时设计确定。

\pnum
\term{任务边界规则}：引用不跨任务边界。进入任务的闭包，其捕获集合中不得含有引用捕获，所有捕获必须为移动捕获（\ref{expr.closure}）；任务的执行结果经\tcode{Future}移动传出。闭包捕获检查复用最小捕获推断的结果：推断为引用捕获的变量使任务创建构成编译错误，诊断应指出相应变量并建议显式移动捕获或\tcode{clone()}。

\pnum
由此，任务之间不存在语言级别的共享：并行任务各自独占其拥有的值，数据竞争在语言层面不可构造。不透明类型（\ref{type.opaque}）可以定义产生共享句柄的\tcode{clone()}；此类句柄的并发安全性由类型作者保证，与\tcode{unsafe}和 FFI 处于相同的信任层级。

\pnum
\tcode{await}是任务域内的汇合点；经任务创建产生的\tcode{Future}，对其的\tcode{await}等待对应任务完成并取其结果。任务到操作系统线程的映射由运行时确定，不属于语言语义。
